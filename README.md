# Мини-приложение «Плеер» для Telegram — каталог из @designersformusic

Схема: **плеер** (статика) живёт на GitHub Pages как сейчас, **бэкенд**
(Python) — на Fly.io, обходит историю вашего канала, отдаёт каталог и
раздаёт сами файлы с поддержкой перемотки. GitHub Pages сам Python не
исполняет, поэтому эти две части разнесены.

Почему нельзя проще: Bot API читает только новые посты после того, как бота
добавили в канал, всю уже накопленную историю он не видит. Историю читает
только обычный аккаунт через MTProto (библиотека Telethon) — отсюда и
отдельный сервер.

## Структура

```
index.html, tracks.json, bot.py   — как раньше, плеер и Telegram-бот
server/
  catalog.py       — конфиг + SQLite-хранилище каталога
  app.py            — сам сервер: индексация + отдача /tracks.json и /stream/{id}
  login_local.py    — разовый локальный логин, получить строку сессии
  requirements.txt
  Dockerfile
  fly.toml          — конфиг деплоя на Fly.io
```

## Шаг 1. Получить доступ к Telegram API

1. my.telegram.org → **API development tools** → создать приложение,
   получить `api_id` и `api_hash`.
2. Локально (на своём компьютере, не на сервере):
   ```bash
   cd server
   pip install telethon
   export API_ID=12345678
   export API_HASH=ваш_hash
   python login_local.py
   ```
   Введёте номер телефона и код из Telegram. В конце скрипт напечатает
   длинную строку — это **строка сессии**. Сохраните её, она понадобится
   на шаге 3. Относитесь к ней как к паролю: у кого она есть, тот может
   писать и читать от вашего имени.

## Шаг 2. Установить flyctl и завести приложение

```bash
curl -L https://fly.io/install.sh | sh      # или см. fly.io/docs/flyctl
fly auth login
cd server
fly launch --no-deploy   # использует server/fly.toml, спросит имя — можно своё
fly volumes create player_data --size 1     # 1 ГБ под базу и кеш файлов, хватит с запасом
```

## Шаг 3. Секреты и деплой

```bash
fly secrets set \
  API_ID=12345678 \
  API_HASH=ваш_hash \
  STRING_SESSION="строка из login_local.py" \
  CHANNEL="@designersformusic"

fly deploy
```

После деплоя адрес бэкенда — `https://<имя-приложения>.fly.dev` (имя вы
задали на шаге `fly launch`). Проверить, что сервер жив:

```bash
curl https://ваше-приложение.fly.dev/health
curl https://ваше-приложение.fly.dev/tracks.json
```

Первый запуск читает всю историю канала — если треков много, это может
занять несколько минут, смотрите логи: `fly logs`. Дальше сервер сам раз
в 10 минут (`POLL_MINUTES`) проверяет канал на новые посты — ничего
перезапускать не нужно, когда постите новый трек.

## Шаг 4. Подключить плеер к бэкенду

В `index.html` — в начале `<head>`:

```html
<script>
  window.PLAYER_API_BASE = "https://ваше-приложение.fly.dev";
</script>
```

Залейте обновлённый `index.html` в репозиторий тем же способом, что раньше
(Add file → Upload files, имя файла должно совпадать — GitHub перезапишет
старую версию). Плеер сам подтянет каталог с бэкенда при открытии.

Для быстрой проверки без правки файла можно открыть плеер с параметром:
`https://f1gar0s.github.io/vlados/?api=https://ваше-приложение.fly.dev`

## Как это работает изнутри

- `/tracks.json` — отдаёт список треков из SQLite, у каждого `src` вида
  `.../stream/12345?ext=mp3`.
- `/stream/{id}` — при первом обращении к треку скачивает файл с серверов
  Telegram на диск (`data/cache/`), при повторных — раздаёт уже скачанный
  файл с корректной поддержкой `Range`, поэтому перемотка работает. Первое
  проигрывание конкретного трека может занять пару секунд, зависит от
  размера файла — дальше он в кеше.
- Кеш и база лежат в `/app/data` — это примонтированный `fly volumes`, том
  переживает передеплои. Без него всё индексировалось бы заново на каждом
  рестарте контейнера.

## Приватность канала

Если канал приватный, добавьте ещё и `ACCESS_TOKEN` в секреты (`fly secrets
set ACCESS_TOKEN=любая-случайная-строка`) и откройте плеер со своим токеном:
`?api=...&token=ваш_токен`. Без токена запросы к API будут отклоняться
(`401`). Публичный канал в защите не нуждается — он и так открыт всем.

## Стоимость

Fly.io — usage-based: с одной маленькой всегда включённой машиной
(`shared-cpu-1x`, 512 МБ, как в `fly.toml`) и томом на 1 ГБ ожидайте порядка
$3–5 в месяц. Бесплатного тарифа как такового у Fly.io нет, но и подписки
тоже нет — платите только за реально использованные ресурсы. Точные цифры
меняются, актуальный калькулятор: fly.io/docs/about/pricing.

## Что осталось от прошлой версии без изменений

- `bot.py` — кнопка запуска мини-приложения, ничего менять не нужно.
- `tools/` (Audius, локальные файлы) — не понадобятся при этой схеме, но
  можно оставить в репозитории на будущее, если решите смешивать источники.
- Виртуализация списка очереди в `index.html` (порции по 50 треков) —
  уже на месте, справится и с тысячами записей из канала.
